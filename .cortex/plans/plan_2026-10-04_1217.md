## M4 Implementation Plan — AI Investigation Engine

### Context

- 22 objects exist across 5 BANKGUARD schemas (tables, views)
- Cross-region inference is enabled (`ANY_REGION`)
- `COPILOT_USER` role is granted to `ACCOUNTADMIN`
- `V_RETRIEVAL_DOCUMENTS` (23 active policy sections) is ready for Cortex Search indexing
- `V_CUSTOMER_360`, `CUSTOMER_RISK_SCORE`, `RISK_SIGNAL_EVIDENCE`, and `V_TRANSACTION_ENRICHED` provide the structured data foundation
- `V_SIGNAL_POLICY_CHAIN` already connects signals → policies for any customer

### Implementation Steps

**Step 1: Audit Tables (BANKGUARD_AUDIT)**
- Create `AI_DECISION_LOG` table — logs every agent interaction (timestamp, query, response, evidence refs, model, citations)
- Create `INVESTIGATION_FINDINGS` table — structured investigation reports linked to cases

**Step 2: Cortex Search Service (BANKGUARD_REGULATORY)**
- Create `POLICY_SEARCH_SERVICE` on `SEARCH_TEXT` column from `V_RETRIEVAL_DOCUMENTS`
- ATTRIBUTES: `POLICY_DOMAIN`, `RISK_TOPIC`, `STATUS`, `SOURCE_TYPE`
- PRIMARY KEY: `DOCUMENT_ID`
- WAREHOUSE: `COMPUTE_WH`, TARGET_LAG: `1 day`

**Step 3: Semantic View (BANKGUARD_CORE)**
- Create a semantic view `BANKGUARD_RISK_ANALYST` covering:
  - `V_CUSTOMER_360` (customer dimension with balances, counts)
  - `CUSTOMER_RISK_SCORE` (composite risk scores and classification)
  - `RISK_SIGNAL_EVIDENCE` (individual signal details with evidence)
  - `V_TRANSACTION_ENRICHED` (transaction facts with customer context)
  - `FRAUD_ALERTS` and `INVESTIGATION_CASES`
- Define relationships (CUSTOMER_ID joins), metrics, and verified queries
- Include custom instructions for governance (never declare fraud, cite evidence)

**Step 4: Cortex Agent (BANKGUARD_CORE)**
- Create `BANKGUARD_AGENT` with:
  - **Tool 1**: `cortex_analyst_text_to_sql` → `BANKGUARD_RISK_ANALYST` semantic view
  - **Tool 2**: `cortex_search` → `POLICY_SEARCH_SERVICE`
- Instructions encode governance rules:
  - Always cite `[POLICY_ID vVERSION, Section X.X]`
  - Never declare criminal activity
  - Use "potential pattern" / "requires analyst review" language
  - Return "Insufficient evidence" when data doesn't support a conclusion
- Sample questions for the hero case and common analyst queries

**Step 5: Agent Testing**
- Run `SNOWFLAKE.CORTEX.DATA_AGENT_RUN` against hero case CUST-1042
- Verify: risk score returned, signals enumerated, policy citations present, governance language used
- Test a normal customer to verify low-risk response
- Test negative gate (ask about cryptocurrency risk)

**Step 6: SQL Files & Documentation**
- Write SQL files under appropriate directories
- Create `docs/AI_INVESTIGATION_ENGINE.md`
- M4 completion report
